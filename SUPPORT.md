This file explains where to go depending on what you need.

## Before Opening an Issue

Please check:

- [README.md](./README.md)
- [docs/README.md](./docs/README.md)
- [docs/DEPLOYMENT.md](./docs/DEPLOYMENT.md)
- [docs/CONFIGURATION.md](./docs/CONFIGURATION.md)
- [docs/TROUBLESHOOTING.md](./docs/TROUBLESHOOTING.md)

Many setup and runtime questions are already covered there.

## Use GitHub Issues For

Open a GitHub issue for:

- reproducible bugs
- documentation problems
- feature requests
- deployment problems that are not security-sensitive

Use the built-in GitHub issue templates where possible. They are set up for:

- bug reports
- feature requests
- deployment issues
- documentation improvements

When possible, include:

- what you expected
- what happened instead
- environment details
- logs or screenshots
- steps to reproduce

## Security Issues

Do not open a public issue for security vulnerabilities.

Please follow the instructions in [SECURITY.md](./SECURITY.md).

## Configuration and Deployment Questions

If the problem is about setup or deployment, include:

- whether you are using Docker Compose or Helm
- relevant environment values, without secrets
- the failing command
- the exact error output

## Project Status

InfraGate is actively evolving. That means:

- documentation may improve over time
- operational workflows may continue to expand
- some setup paths may still need real-world validation in your environment

Clear bug reports and deployment notes are especially helpful.
